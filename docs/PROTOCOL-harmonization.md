# Protocol: how much of the disagreement between simulated galaxy stellar mass functions can documented definitions explain?

Status: **pre-specified**. Written on 2026-10-14 after looking at the aperture-comparison figures of the EAGLE and COLIBRE papers (to know which apertures each suite offers) and after listing which suites have a z about 0 mass function and how each documents its aperture; **before** any shift, variance, skill or p-value was computed. The analysis code implements this text. Every departure from it is listed under "Deviations" in `docs/ANALYSIS-harmonization.md`, which is generated by the code and reports whatever comes out, including a null result.

## 1. Why this exists

`docs/ANALYSIS-definition-budget.md` asks the same question and cannot answer it: it classifies record pairs by documented definitions and compares median absolute offsets, reuses each curve in many pairs, has 2 to 9 matched pairs per test, and 0 of 16 tests survive correction. It also measures offsets vertically (log Phi at fixed M*), which in the exponential tail of the mass function depends on each curve's slope rather than on the definition. Mass definitions act on masses, so the natural coordinate is horizontal: the stellar mass at fixed abundance.

## 2. Coordinate

For a curve y(x) = log10 Phi(log10 M*) the abundance-matched mass at level phi is

    m(phi) = the largest x on the curve at which y crosses phi from above,

taken by linear interpolation between neighbouring points, defined only where the curve is inside its own x range and both neighbouring points are at most 0.6 dex apart (the rule of the existing analysis). Levels: phi = -2.00, -2.25, ..., -4.50 (11 levels; log10 cMpc^-3 dex^-1). A curve is used only if its y unit contains `dex^-1`, i.e. the per-dex normalisation is stated: `log10(cMpc^-3 dex^-1)` and `log10(Mpc^-3 dex^-1)` are the same physical quantity under two spellings (the old analysis treated them as different, this one does not, and says so). A density frame stated as comoving or left unspecified is accepted at z <= 0.2 (physical versus comoving changes y by at most 0.08 dex there). Records with y unit `log10(Mpc^-3)`, whose per-dex normalisation is not stated (SIMBA, the Dave+20 TNG record), are excluded and added back in S7.

Sampling noise (few galaxies per bin in the tail) is **not** modelled; it inflates the dispersion before and after harmonization alike and lowers the ceiling on R. This is declared as a limitation and addressed by the sensitivity analysis S3.

## 3. Data

Primary epoch: records with `epoch.zRepresentative` <= 0.2 of relation `gsmf`, kind `simulation`, representation `points`, at least 5 points, population `all`. One curve per suite, chosen by the website's own fiducial rule (`primaryUnits` in `highline/logic.js`, ported and tested against it), then the record of that unit whose epoch is nearest z = 0. A suite enters a level phi only if its curve defines m(phi); a level is used only if at least 4 suites define it.

Aperture library: every set of GSMF records from the **same run** at the same epoch that differ only in `massDefinition` (the within-run pairs the existing analysis already detects, plus the EAGLE and COLIBRE aperture figures added with this protocol). The library records are excluded from the choice of fiducial curves.

## 4. Operators

**IMF.** Reference Chabrier 2003. Standard offsets of the website (`IMF_DEX`: Kroupa -0.025, Salpeter -0.235 dex in stellar mass): m'(phi) = m(phi) + (IMF_DEX[chabrier03] - IMF_DEX[imf]). No uncertainty is attached (sensitivity S4: plus or minus 0.05 dex).

**Aperture.** Reference aperture: 3D 30 pkpc (the one aperture that all three library suites share). For a library suite s and a pair of definitions A to B, the mass map is estimated by abundance matching: delta_s,A->B(M) = m_B(phi) - m_A(phi) evaluated at M = m_A(phi), on the phi levels above (finer grid, step 0.05, for the universality test). Maps are defined only inside the overlap of the two curves' solid ranges.

A suite curve in definition A is harmonized to 30 pkpc by m'(phi) = m(phi) + delta_A->30(m(phi)), with delta the mean of the available library suites' maps for that pair (the **universal map**); where the map is not defined at that mass the level is left uncorrected and flagged. Pairs with no measured map (2 R_half outside Illustris, `aperture-Rg`, `caesar-6dfof-galaxy-total`, `unspecified`) are not corrected.

**Mass scatter (amendment A1, see the end).** A record that states a lognormal scatter of sigma dex added to its stellar masses (at z about 0 only the FLAMINGO mass functions: "include the 0.3 dex random lognormal stellar-mass scatter expected in observed data") is brought to sigma = 0 by Richardson-Lucy deconvolution with a Gaussian kernel of that width in log mass: the curve is interpolated on a 0.02 dex grid, extended beyond its ends by its end slopes, and 10 iterations are run (the count is fixed; more iterations amplify noise). m(phi) is read from the deconvolved curve and kept only where the level lies at least 3 sigma above the lower end of the curve. The aperture map is applied after this step (the scatter is added to the aperture mass). Nothing is done to curves without a stated scatter, so no suite is smoothed that does not need it.

**Validation gate V1.** The released COLIBRE tables hold the same runs without (`gsmf_raw`) and with (`gsmf_with_edd_bias`, sigma(z) = min(0.1 + 0.1 z, 0.3) dex) Eddington scatter. The operator is used only if deconvolving `gsmf_with_edd_bias` of L200m6 at z = 2, 3, 4 (sigma = 0.3) reproduces `gsmf_raw` to within 0.05 dex in m(phi) at every level where both are defined; the same check is reported for the forward convolution and for z = 0 and 1. If the gate fails the scatter is not corrected, FLAMINGO is "uncorrectable", and E2 lets it take any sigma in {0, 0.1, 0.2, 0.3}.

## 5. Estimands and decision rules

For the set of suites and levels above, V(phi) is the unbiased sample variance of m_s(phi) across suites, and V is its mean over phi.

**E1 - documented definitions (primary).** R_doc = 1 - V_harmonized / V_raw, harmonizing IMF, mass scatter (A1) and every aperture that has a measured map. At each level only suites for which both the raw and the harmonized mass are defined are used (complete cases), so the two variances always describe the same suites. R is also reported for each operator alone (IMF, scatter, aperture) and with each operator left out. Reported for all levels and for the body (phi from -2.0 to -3.0) and tail (-3.25 to -4.5) separately. *Success* requires all three: the lower end of the 95 % percentile interval of a cluster bootstrap over suites is above 0; the p-value of the label-permutation test (E1 uses the correction of another correctable suite) is below 0.05; and the sign of R_doc is the same in sensitivity analyses S1 and S2. Otherwise the conclusion is "not detected", with the power analysis E4 stating what could have been detected.

**E2 - upper bound from undocumented definitions.** Suites whose aperture class has no measured map (unspecified, `aperture-Rg`, `caesar-6dfof-galaxy-total`) are allowed any aperture class of the library. R_ub is the largest variance reduction over all assignments (exhaustive; the number of classes to the power of the number of such suites, at most a few hundred). It is the most that aperture alone could explain. Because a maximum over assignments is optimistic, it is compared with two null distributions: the same maximisation with every library map reflected in mass (delta(M_lo + M_hi - M)), and with every map sign-flipped. R_ub is reported as exceeding the null only if it is above the 95th percentile of both.

**E3 - universality of the aperture map.** For each definition pair measured in at least three library suites (30 pkpc to total is the only one expected), leave one suite out, predict its map by the mean of the others on their common mass range of at least 0.5 dex, and compute the skill 1 - MSE_model / MSE_zero. Reported per fold with the range. "Universal" is claimed only if every fold has positive skill and the mean absolute error of the prediction is below 0.05 dex; otherwise the map is reported as suite dependent, and its between-suite standard deviation is used as the transfer uncertainty in E1.

**E4 - power (injection and recovery).** Starting from the harmonized curves, each correctable suite is given an aperture class drawn from the library, the inverse of its map is applied to produce raw curves with known definition differences, scaled by lambda in {0, 0.5, 1, 2}; the E1 pipeline is run on 200 random draws per lambda. Reported: the recovered R against the true R, and the fraction of draws meeting the E1 success rule, which gives the smallest definition effect the present suites could have detected.

## 6. Sensitivity analyses (reported, not used to choose)

- **S1** Reference aperture 50 pkpc instead of 30 (maps inverted or composed through 30 pkpc where only that is measured).
- **S2** Aperture map applied as a function of abundance, delta(phi), instead of mass.
- **S3** Restrict to phi >= -3.75.
- **S4** IMF offsets changed by plus or minus 0.05 dex.
- **S5** One random eligible record per suite (the unit chosen at random among non-variant units), 200 draws, instead of the website's rule.
- **S6** Leave each suite out in turn (influence).
- **S7** Include the records whose per-dex normalisation is not stated (SIMBA), assuming per dex and comoving.
- **S8** Convolve every suite to sigma = 0.3 dex instead of deconvolving FLAMINGO (reference sigma = 0.3; a placebo for the smoothing artefact is reported with it).
- **S9** Add a random error of 0.03 dex (the validated accuracy) to the deconvolved masses, 200 draws.

## 7. Limitations declared in advance

1. The library has three codes (Illustris/AREPO, EAGLE/GADGET-SPH, COLIBRE/SWIFT-SPH) and one definition pair common to all; maps for 30 to 50 pkpc rest on COLIBRE alone and are applied to FLAMINGO on the assumption of transfer.
2. "Total" is a family: SUBFIND subhalo mass (Illustris), mass of all bound particles (EAGLE no aperture, COLIBRE all bound) are treated as one class.
3. Curves are digitized from figures (stated uncertainty 0.01 to 0.02 dex); the EAGLE figure's legend (10, 30, 100 pkpc, Petrosian, no aperture) disagrees with its caption (30, 50, 100 pkpc); the legend, which is what is drawn, is used.
4. Suites are not independent samples of a population of simulations; the bootstrap treats them as exchangeable.
5. A result of "definitions explain little" at z about 0 does not say they explain little at other epochs or in other relations; those are untested.
6. Nothing here corrects a stored record. All harmonized curves exist only inside the analysis.

## 8. Amendments

**A1 (2026-10-14, before any E1 to E4 statistic was computed).** The mass-scatter operator and gate V1 above were added. Reason: the FLAMINGO records state that their mass functions include 0.3 dex of random lognormal mass scatter, the existing plausibility screen flags FLAMINGO as the largest z about 0 outlier for that reason, and an analysis that left a documented, large definition difference out of "documented definitions" would understate them. What had been looked at when this was decided: the record text, and how well the operator reproduces the released COLIBRE tables (about 0.03 dex against needed corrections of 0.1 to 0.3 dex); no cross-suite variance, reduction or p-value. The primary reference is sigma = 0 (deconvolve the one suite that needs it) rather than convolving every other suite to 0.3 dex, because the latter smooths curves that need no correction and lowers the dispersion by itself; the convolve-all variant is sensitivity S8. S9 adds a 0.03 dex random error to the deconvolution (the validated accuracy).
