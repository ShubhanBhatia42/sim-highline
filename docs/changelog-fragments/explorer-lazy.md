Changelog bullets (Unreleased):

- Explorer: the plotted data now load one relation at a time. A first visit (stellar mass function) transfers 225 kB compressed instead of 794 kB (3.1 s to usable on the slow-phone test instead of 7.4 s, measured on one machine), and opening another relation fetches 1 to 79 kB more (the mass-size relation: 70 kB). The page embeds a thin index of all 1,872 records (45 kB compressed), so the relation list and counts, the What exists view, search and shared links need no fetch; the comparison-against-observations, disagreement and distribution views fetch the relations they read first (the disagreement view: 770 kB in all). A relation's data file that is missing, damaged, from another build or slow gives a message that names the relation and a Try again button, not a blank plot.
- No displayed or downloaded number changes. Checked by capturing the Explorer's output for 1,022 fixed states before and after (every relation at three epochs and in the over-time view, the Get data panel, CSV, JSON, Python, BibTeX, methods text, figure SVG and pack, embed code and links for every relation, the evidence text and computed points of all 1,872 records, every pairwise comparison verdict within each relation, the Tension, Disagreement and Distribution views, Check your run tables, example runs and shared-run links, search results, permalinks opened cold): 1,022 of 1,022 identical, 67.8 million characters compared. This is an internal check by the same author; no outside reviewer has seen it.
- Explorer: `highline.html` has to be served over http (as on the site). Opened straight from a file, the browser refuses the data fetch and the page says so.
- Tests: `scripts/test-explorer-data.mjs` fails if a relation's data file is missing or differs from `data/curve-index.js`, if a file is left over, or if the embedded index grows back (and shows that nine kinds of damage are caught); `scripts/test-resilience.mjs` covers a missing, damaged, wrong, slow and unreachable data file and leaving a view while its data load; `scripts/test-performance.mjs` now budgets the first visit at 260 kB (was 800 kB), a second relation at 80 kB and the view that reads every relation at 880 kB.

Hand-written counts or numbers elsewhere that this changes: none found (the old 800 kB budget was only in `scripts/test-performance.mjs`). `docs/ARCHITECTURE.md` has a new short section and two edited lines; `docs/README.md` gets one line for this folder (lint requires every item in `docs/` to be listed; any other branch adding the same line only needs one copy kept). `data/curve-index.js` and everything Node tools read are unchanged.
