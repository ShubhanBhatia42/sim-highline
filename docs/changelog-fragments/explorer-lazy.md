Changelog bullets (Unreleased):

- Explorer: the plotted data now load one relation at a time. A first visit transfers 225 kB compressed instead of 799 kB (7.4 s to usable on the slow-phone test before, 3.3 s after, on one machine), and opening another relation fetches 1 to 79 kB (the mass-size relation: 70 kB). The page embeds a thin index of all 1,872 records, so the relation list and counts, the What exists view, search and shared links work without a fetch; the comparison-against-observations, disagreement and distribution views fetch the relations they read first. A relation's data file that is missing, damaged, from another build or slow produces a message that names the relation and a Try again button, not a blank plot. No displayed or downloaded number changes: 1,020 of 1,022 captured states (every relation at three epochs, downloads, the evidence text of every record, the Check your run tables, shared links) were identical before and after, and the two that differed were then fixed and re-checked.
- Explorer: `highline.html` has to be served over http (as on the site); opened straight from a file, the browser refuses the data fetch and the page says so.
- Tests: `scripts/test-explorer-data.mjs` fails if a relation's data file is missing or differs from `data/curve-index.js`, or if the embedded index grows back; `scripts/test-resilience.mjs` covers a missing, damaged, wrong and slow data file and a lost connection; `scripts/test-performance.mjs` now budgets the first visit at 260 kB (was 800 kB), a second relation at 80 kB, and the view that reads every relation at 880 kB.

Hand-written counts or numbers elsewhere that this changes: none found (the old 800 kB budget is only in `scripts/test-performance.mjs`). `docs/ARCHITECTURE.md` has a new short section. `data/curve-index.js` and everything Node tools read are unchanged.
