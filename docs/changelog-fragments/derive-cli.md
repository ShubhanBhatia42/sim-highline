## Changelog bullets (Unreleased)

- New command `sim-highline derive`: records of the standard relations (stellar mass function, star-forming main sequence, specific SFR, quenched fraction, size, stellar-to-halo mass ratio, black-hole mass, stellar and gas metallicity, HI and H2 fractions) from a simulation catalogue you hold, in the project's record format, with the dataset's cuts and definitions. Formats: Subfind group catalogues (Illustris, IllustrisTNG, CAMELS), CAESAR (SIMBA), SOAP (FLAMINGO, COLIBRE) and a table exported from the EAGLE database. A definition is taken from what you state or from what the file says, never assumed: units, h, Omega_m, box size, IMF, baryon particle mass and the mass aperture that neither the file nor you give stop the run with a list of everything missing or in conflict and the option that settles each (nothing is written, exit code 2). `sim-highline compare run.json [--relation gsmf ...]` prints, per relation, the nearest published observations and simulations that the website's comparability rules allow (the same code as `compare_run`) and, in words, why the others are not comparable; `derive --compare` does both. `docs/DERIVE-CLI.md` has a worked example on the synthetic catalogues in `tests/derive-cli/`. Checked on synthetic catalogues only (no real TNG, SIMBA, FLAMINGO, COLIBRE or EAGLE file was available); internal check only, no outside reader.
- The derivation code of `scripts/derive_{subfind,caesar,soap,eagle}_relations.py` and `scripts/distribution_stats.py` moved into the importable module `sim_highline_derive.py` (in the wheel; `pip install "sim-highline[derive]"` adds h5py); the scripts are thin wrappers with an extra optional `--out`. Their output is unchanged: byte-identical to before on the catalogues of the older pipeline tests (old and new scripts diffed), and `scripts/test_derive_cli.py` compares their output on the shipped catalogues with hashes recorded from the old scripts.
- `data/export/sim-highline-rules.json` now also carries the plain names of the comparability keys (`labels`, from `KEY_LABEL` in `compare.js`), so that the command line can word its reasons as the Explorer does; older copies of the file still work (the keys are then shown unglossed).
- Known difference, not changed: for the same catalogue `derive` writes `massDefinition` in the dataset's vocabulary (`aperture-2rhalf-stars`, `aperture-50pkpc`), while the scripts keep the labels they always wrote (`aperture-2x-stellar-half-mass-radius`, `aperture-50pkpc-exclusive`), which no record in the dataset uses; changing them would change the scripts' output.
