# Decisions

Newest first. Each entry says what was decided, why, and what would reverse it.

## 2026-10-23

- **Compilation curves are corrected only by a recorded, reversible list, and only with evidence.** Reason: 50 curves from the SWIFT comparison compilation were checked against their papers and several were wrong (Grazian 2015 and Gonzalez 2011 numerically; others in labels or flags). A numeric change needs two independent pieces of evidence, a label or flag change one; each corrected record keeps a hash of its points as ingested so the change can be undone (`data/compilation-corrections.json`, `docs/COMPILATION-CHECK.md`). Reverses if the compilation's maintainers publish a corrected version.
- **Aperture and weighting conversions are measured in four codes and reported, not applied.** Reason: IllustrisTNG, SIMBA, Astrid and Swift-EAGLE disagree with one another on the same conversion, so a single factor would be wrong for at least two of them (`docs/CONVERSIONS.md`). Reverses if a conversion turns out to agree across codes within the seed scatter.
- **Digitized curves are replaced by a table whenever one exists and matches the plotted numbers, and the page says how many were.** Reason: a table is worth more than any extraction check. The wording on the data-quality page is computed from the records' tiers, not typed.
- **Sources are credited by `provenance.attribution`, from `data/attribution.json`, and the credit is a column in the downloads.** Reason: a record reproduces numbers someone else produced; the Evidence panel and the BibTeX file now name them.
- **Records that cannot yet be drawn faithfully are held in `data/staged/` and not in the dataset.** Reason: density contours cannot be stored as curves (they fail the monotone-x rule), per-mass-bin histograms would add dozens of panels, and one X-ray fit has an unstated halo-mass pivot; withholding is better than a wrong or crowding curve (`data/staged/README.md`).
- **The fifth study (does the shape of the star-formation distribution separate the codes?) was written down before the data were ingested, and its rule was amended once, before any distance existed.** Reason: testing the code on synthetic worlds showed that the first rule would call identical codes "shape adds separation". Amendment A1 compares each difference with the same-code controls of the same split. The protocol, the amendment and the ingest are separate commits in that order.
- **Usage counts are off by default and opt-in; Do Not Track is honoured.** Reason: the success rule is about outside use, but a visitor should not be counted without a choice. Nothing is sent until `data/usage-counts.json` is enabled.
- **A backup maintainer is named as a need, not as a person.** Reason: `docs/GOVERNANCE.md` lists the single points of failure and what a backup would need; naming someone is the maintainer's decision.

## 2026-10-18

- **One documented set of IMF offsets (Kroupa -0.040, Salpeter -0.218 dex to Chabrier), the compilation's factors; registered studies stay frozen.** Reason: two sets were in use that differed by 0.015 to 0.017 dex, one of them with no stated origin, so converted observation curves and converted simulation curves were not on the same convention. The set is a convention (population-average conversions are uncertain at about 0.02 dex), not a measurement. The harmonization and model-form studies were registered with the old offsets and keep them (`HARM_IMF_SET=current` re-runs the harmonization with the new ones as an exploratory check: the ratio R moves from 0.151 to 0.155, the permutation p from 0.111 to 0.108, and the verdict (not detected) does not change; `data/analysis/harmonization-imf-sensitivity.json`). Reverses if a better-sourced set is found; change `data/imf-offsets.json` and `compare.js` together (a test keeps them equal).
- **A definition is added only from a sentence in the paper that says it, quoted and hashed; readings that need an inference are listed as "read, not stated".** Reason: a wrong definition makes a comparison look fair that is not, which is worse than an open one. Rejected on those grounds in the second reading: ASTRID stellar mass "in the FOF halo" (only implied), FIREbox "comoving" (only implied by the box volume), NewHorizon SED mass for the whole mass function (stated for one curve only). Reverses if the authors confirm one.
- **The audit of what was changed in the data is generated from the records and from the compilation's own scripts, and checked in CI.** Reason: a hand-written list drifts. `scripts/audit_conversions.py --check` fails when the committed counts differ from the records.

## 2026-10-16

- **The Explorer writes its address at most every 150 ms; the harmonization result is written to 10 significant digits.** Reasons: Safari and Firefox refuse more than 100 `history.replaceState` calls in 10 seconds, which a dragged slider can reach, and the last digits of the harmonization result differ between machines (about 1e-13), which made the CI "generated files are up to date" check fail on a clean runner. Neither changes a number anyone reads: the registered analysis script is touched only in how it saves floats, the values agree to 10 digits. Reverses if a browser adds a way to ask for more writes or if the numeric stack is pinned bit-for-bit.
- **A speed-up of the emulator code that changes no number.** `quad_features` (scripts/modelform_stats.py) now builds the polynomial features from precomputed index arrays, and `_grad_pred` and `astro_x` (scripts/analyze_model_form.py) build their points without loops. These sit under the registered analyses, so the rule was: results must be identical bit for bit. Checked on random inputs (all dimensions and degrees) and on a full distance search (same distance to the last digit, same hash of the result), and by the saved-output tests of both analyses. Reason: the joint-reachability test took about ten minutes; it now takes under two on four cores. Reverses if any saved result ever differs.
- **The slow tests are skipped locally when nothing they read has changed; CI always runs them.** Reason: a check nobody runs because it is slow protects nothing. `FRESH=1` forces them.
- **The share-preview images are generated by a script and committed.** Reason: the chart on each card is the page's own chart, which needs a browser to draw; a build that needs a browser everywhere would be slower and more fragile. A stale image is a cosmetic fault, so it is regenerated by hand (`make og`).
- **Content-Security-Policy as a meta tag with the hash of every inline script.** Reason: the host (GitHub Pages) does not let us set headers. A meta policy cannot restrict framing, so that part is not covered. Styles stay `unsafe-inline` because the pages use inline style attributes.
- **No separate Research page.** The four studies stay on the front page below the tools and on the Studies page. Reason: a second layer of navigation adds a click for nobody's benefit. Reverses if visitors cannot find them.
- **The menu calls the dials page "Dials".** The address stays `retune.html` so links survive.
- **The front door is "check your own run" and "turn the dials", not the studies.** Reason: the studies are evidence, the tools are what someone returns for. Reverses if pilot users go to the studies first.
- **Study codes (S1 to S4) are dropped from everything a visitor reads.** Reason: nobody remembers them. The files keep their names; pages use plain titles.
- **Retune matches one property at a time by default.** Reason: matching everything at once reports "agree on 2 of 11", which hides what tuning can do. Matching one property shows the trade-off it causes.
- **Native units (dex, fraction) are shown beside noise units.** Reason: "4.8 noise units" means nothing to a reader; one noise unit is 0.04 to 0.18 dex depending on the property.
- **Success and stopping rules are written down (PROJECT.md).** Reason: the decision to continue should rest on outside use, not on how much has been built.
